# hermes-vk — канал ВКонтакте для Hermes Agent

[![tests](https://github.com/TemArt90/hermes-vk/actions/workflows/tests.yml/badge.svg)](https://github.com/TemArt90/hermes-vk/actions/workflows/tests.yml)
[![license](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

Плагин-адаптер, подключающий [Hermes Agent](https://hermes-agent.nousresearch.com/docs) к сообществу
ВКонтакте. Входящие сообщения — через **Bots Long Poll API**, исходящие — через `messages.send`.
Публичный адрес, домен и вебхук **не нужны**: Long Poll — это исходящее длинное соединение, поэтому
канал работает и там, где входящие подключения недоступны или режутся провайдером.

Реализация независимая, на Python, под контракт платформенных плагинов Hermes. Поток и форматы
(Long Poll, клавиатуры, `format_data`) разобраны по образцу плагина
[pfrankov/openclaw-vk](https://github.com/pfrankov/openclaw-vk) — см. [NOTICE](NOTICE).

> **English summary** — a VK (VKontakte) channel plugin for Hermes Agent. Inbound over the Bots
> Long Poll API (no public URL, no webhook), outbound over `messages.send`; markdown → VK
> `format_data`, inline callback keyboards for clarify/approval prompts, photo/document/voice
> uploads, native video upload with an optional personal token, pairing-based access control, cron
> delivery. Install by cloning into `~/.hermes/plugins/platforms/vk`, then
> `hermes plugins enable vk-platform`. Apache-2.0.

## Возможности

| Возможность | Как работает |
|---|---|
| Текст | `messages.send`, нарезка под лимит VK (4000 символов с запасом) |
| Разметка | Markdown → VK `format_data`: **жирный**, *курсив*, ссылки; офсеты в UTF-16 |
| Таблицы | VK их не умеет — конвертируются в «жирный заголовок + пункты»; код в ``` остаётся кодом |
| Цитаты | `> текст` → курсив; в беседе ответ уходит с цитатой входящего сообщения |
| Картинки и файлы | `photos`/`docs.getMessagesUploadServer`; подпись и вложение — одним сообщением |
| Голосовые | Ogg Opus через `ffmpeg`; если `ffmpeg` нет — файл уходит документом |
| Кнопки | inline-клавиатура + `message_event`: вопросы агента (clarify), подтверждение опасных команд, подтверждение слэш-команд |
| Выбор кнопками | `/model` (провайдер → модель), `/reasoning`, `/fast` рисуются интерактивно: ядро отдаёт список адаптеру через `send_model_picker` / `send_choice_picker`, тап переключает и показывает ответ ядра в том же сообщении. Дорогая модель сначала спросит подтверждение (тот же guard ядра) |
| Интерактивные списки | `vk_checklist` — сообщение с кнопками-позициями: тап вычёркивает позицию в том же сообщении. Состояние на диске (`vk_widgets.json`), переживает рестарт; до 8 позиций на страницу плюс перелистывание (у inline-клавиатуры жёсткий предел VK — 10 кнопок, замерено) |
| Входящие медиа | фото, документы и голосовые скачиваются в медиа-кэш агента (фото доступно vision). **Видео скачать нельзя ни с каким ключом** — VK не отдаёт ссылок на файлы (замерено живьём 04.10.2026), входящее видео приходит пометкой; см. «Ограничения» |
| Доступ | штатные гейты Hermes (`VK_ALLOWED_USERS` / `VK_ALLOW_ALL_USERS`) + pairing-код |
| Расписание | `deliver=vk`, в том числе в списке (`deliver=email,vk`) для cron-отчётов |
| Клавиатура команд | опционально (`VK_COMMAND_KEYBOARD=true`): кнопки `/help`, `/status`, `/new`, `/stop` над полем ввода — тап отправляет команду. Выключить: `VK_COMMAND_KEYBOARD=false` + рестарт. Можно по каждому чату: `VK_COMMAND_KEYBOARD_BY_PEER='123456:false,777777:true'` |
| Резервный опрос | опционально (`VK_FALLBACK_POLL_ENABLED=true`): если Long Poll замолчал, раз в `VK_FALLBACK_POLL_INTERVAL_SECONDS` (по умолчанию 60 с) адаптер опрашивает историю последних бесед — сообщение доедет, даже если долгий запрос завис |
| Исходящее видео | `.mp4`/`.mov`/`.webm` уходят нативным вложением VK, если задан личный токен (`VK_USER_TOKEN`): `video.save` — метод пользовательского уровня, ключу сообщества VK отвечает ошибкой 5 (проверено живьём). Вложение несёт `access_key` (`video<owner>_<id>_<key>`) — без него получатель видит непроигрываемое приватное видео. Работает и в живом ответе агента, и в доставке по расписанию / `hermes send`. Без личного токена файл доезжает документом — откат встроен, отчёт не теряется. Как получить ключ — см. «Личный токен: как получить» |
| Беседы | по умолчанию отвечает на все сообщения. С `VK_REQUIRE_MENTION=true` — только когда бота позвали: `[club<id>|Имя]`, `@club<id>` или имя сообщества. Отдельной беседе можно вернуть или включить гейт точечно: `VK_REQUIRE_MENTION_BY_PEER="<peer_id>:true,<peer_id>:false"` |
| Вложения | скачиваются в кэш агента, чтобы агент их «увидел». Выключить приём файлов: `VK_DOWNLOAD_ATTACHMENTS=false`; предел размера: `VK_MAX_ATTACHMENT_BYTES` (по умолчанию 20 МБ) |
| Правка на месте | длинные ответы и прогресс обновляются в уже отправленном сообщении (`messages.edit`), а не приходят вторым. Правка идёт простым текстом: у `messages.edit` нет `format_data`, и он не умеет разбивать — слишком длинное содержимое отправляется заново |
| Статусы одним пузырём | `send_or_update_status`: поток служебных уведомлений одного типа («⏳ Работаю — N мин», «↪ Запуск перенаправлен») правит одно сообщение, а не плодит по строке на обновление. Тот же ключ живёт 10 минут, потом начинается новый пузырь |
| Уборка сообщений | `delete_message` (`messages.delete` по глобальному id, `delete_for_all`): промежуточные пузыри убираются в конце хода при `display.cleanup_progress: true`, системные — по TTL. Замерено живьём: удаление возвращает `response: 1` и сообщение исчезает из истории |
| Реакции | опционально (`VK_REACTIONS_ENABLED=true`): 👌 на ваше сообщение пока агент работает, затем 👍 или 👎. Номера реакций настраиваются (`VK_REACTION_PROGRESS` / `VK_REACTION_OK` / `VK_REACTION_FAIL`), 0 отключает шаг |

Кнопки используют общую конвенцию Hermes (`cl:` / `ea:` / `sc:`), поэтому сценарии работают так же,
как в Telegram: нажатие подтверждает выбор, а не присылает текст; неавторизованный нажимающий
получает отказ; кнопка одноразовая.

## Установка

```bash
git clone https://github.com/TemArt90/hermes-vk ~/.hermes/plugins/platforms/vk
hermes plugins enable vk-platform
```

Затем `hermes gateway restart` — **в отдельном терминале**: изнутри работающего шлюза команда
блокируется самим шлюзом.

Требования: Hermes Agent (используется его Python-окружение; `aiohttp` там уже есть) и, только для
голосовых, `ffmpeg` в `PATH`. Своего веб-сервера, домена и сертификата не требуется.

## Настройка сообщества (действия человека в ВК)

1. Создайте **сообщество** (группу или публичную страницу).
2. `Управление` → `Сообщения` → включить сообщения.
3. `Управление` → `Работа с API` → `Ключи доступа` → **Создать ключ** с правами:
   - «Сообщения сообщества»;
   - «Управление сообществом» — без него **не работает Long Poll API**;
   - «Фотографии» и «Документы» — если нужны картинки и файлы в ответах.
4. `Управление` → `Работа с API` → `Long Poll API`: включить, в «Типах событий» отметить
   **«Входящие сообщения»** и **«Действие с сообщением»** — без второго кнопки-варианты будут
   «крутиться» без реакции.
5. Для ответов в беседах: `Управление` → `Сообщения` → `Настройки для бота` →
   «Разрешать добавлять сообщество в чаты».
6. Для кнопок: там же включить **«Чат-бот»** — иначе VK отвечает ошибкой 912 на любую клавиатуру,
   и адаптер вынужден деградировать до нумерованного текста.
7. Токен положить в `~/.hermes/.env` (в переписке токен не передаём и не принимаем):

```dotenv
VK_TOKEN=vk1.a.ваш_ключ
VK_HOME_CHANNEL=ваш_vk_id          # куда слать отчёты по расписанию
VK_ALLOWED_USERS=ваш_vk_id         # или оставить пустым и подтвердить pairing-кодом
```

## Конфигурация

| Переменная | Обязательна | Назначение |
|---|---|---|
| `VK_TOKEN` | да | Ключ доступа **сообщества** («Сообщения сообщества» + «Управление сообществом») |
| `VK_HOME_CHANNEL` | нет | peer id для доставки cron-отчётов (`deliver=vk`) |
| `VK_ALLOWED_USERS` | нет | Список VK id через запятую, кому разрешено писать боту |
| `VK_ALLOW_ALL_USERS` | нет | Разрешить всем (только для тестов) |
| `VK_QUOTE_IN_GROUPS` | нет | Цитировать входящее в беседах (по умолчанию `true`) |
| `VK_COMMAND_KEYBOARD` | нет | Клавиатура с командами над полем ввода (по умолчанию `false`) |
| `VK_COMMAND_KEYBOARD_BY_PEER` | нет | Переопределить клавиатуру для конкретных чатов: `123456:false,777777:true` (остальные наследуют `VK_COMMAND_KEYBOARD`) |
| `VK_FALLBACK_POLL_ENABLED` | нет | Страховка: при молчащем Long Poll раз в интервал опрашивать историю бесед (по умолчанию `false`) |
| `VK_FALLBACK_POLL_INTERVAL_SECONDS` | нет | Интервал резервного опроса (по умолчанию `60`, минимум `15`) |
| `VK_FALLBACK_POLL_BATCH_SIZE` | нет | Сколько бесед просматривать за проход (по умолчанию `20`) |
| `VK_DEDUPE_TTL_SECONDS` | нет | Окно дедупликации входящих апдейтов (по умолчанию `900`; меньше `30` — игнорируется, остаётся умолчание) |
| `VK_USER_TOKEN` | нет | **Личный** ключ ВКонтакте (ваша страница, права «Видео») — только для нативной отправки видео: `.mp4` уходит плеером VK вместо файла. Входящее видео скачать нельзя ни с ним, ни без него (VK не отдаёт ссылок на файлы). В логах маскируется, в `extra` намеренно не подставляется. Как получить — см. «Личный токен: как получить» |
| `VK_API_VERSION` | нет | Версия VK API (по умолчанию `5.199`) |
| `VK_REQUIRE_MENTION` | нет | В беседах отвечать только при упоминании бота (по умолчанию `false` — отвечает на всё) |
| `VK_REQUIRE_MENTION_BY_PEER` | нет | Исключения по беседе: `"<peer_id>:true,<peer_id>:false"`; неперечисленные наследуют общий флаг |
| `VK_MENTION_PATTERNS` | нет | Свои шаблоны упоминания через запятую вместо автоматических (по id сообщества и его имени) |
| `VK_DOWNLOAD_ATTACHMENTS` | нет | Скачивать вложения из чата в кэш агента (по умолчанию `true`) |
| `VK_MAX_ATTACHMENT_BYTES` | нет | Предел размера скачиваемого вложения (по умолчанию `20971520` = 20 МБ) |
| `VK_REACTIONS_ENABLED` | нет | Реакции-подтверждения на входящее (по умолчанию `false`) |
| `VK_REACTION_PROGRESS` | нет | Номер реакции «в работе» (по умолчанию `10` = 👌; `0` — не ставить) |
| `VK_REACTION_OK` | нет | Номер реакции успеха (по умолчанию `4` = 👍; `0` — снимать реакцию) |
| `VK_REACTION_FAIL` | нет | Номер реакции ошибки (по умолчанию `8` = 👎) |
| `VK_GROUP_ID` | нет | ID сообщества; обычно не нужен — `groups.getById` определяет его из токена |

id сообщества определять вручную не нужно: адаптер спрашивает его у VK по токену.

## Личный токен: как получить

Личный ключ нужен **ровно для одного**: нативная отправка исходящего видео (`.mp4` уходит плеером VK, а
не файлом). `video.save` — метод пользовательского уровня, ключу сообщества VK отвечает ошибкой 5
«User authorization failed» (замерено 03.10.2026 нашим собственным вызовом). Входящее видео скачать
нельзя ни с каким ключом — замерено 04.10.2026, разбор в
[docs/vk-id-auth-flow.md](docs/vk-id-auth-flow.md).

Если ключ не удаётся получить в интерфейсе dev.vk.com, в репозитории есть инструмент, который ведёт
через Authorization Code Flow и **никогда не печатает** ни токен, ни секрет приложения: значения
пишутся прямо в `~/.hermes/.env` (права `600`), в вывод попадают только длины и ответы VK.

```bash
cd ~/.hermes/plugins/platforms/vk
P=~/.hermes/hermes-agent/venv/bin/python

# 1. Секрет приложения («Защищённый ключ») — в файл, не в чат и не в аргументы командной строки
install -m 600 /dev/stdin ~/.hermes/vk-app-secret      # вставить ключ, Ctrl-D

# 2. Ссылка согласия (секретов в ней нет)
$P scripts/vk-user-token.py authorize --app-id <ID> --flow implicit    # или --flow code / vkid

# 3. Открыть ссылку, подтвердить доступ «Видео», затем одно из:
$P scripts/vk-user-token.py store --token <access_token из адресной строки>   # implicit
$P scripts/vk-user-token.py exchange --app-id <ID> --code <code>              # code flow

# 4. Проверить: ключ принят? есть право «Видео»?
$P scripts/vk-user-token.py status

# 5. Если VK вернул refresh_token и ключ короткий — обновление без новой авторизации
$P scripts/vk-user-token.py refresh --app-id <ID>

# 6. Канал подхватывает ключ при рестарте
hermes gateway restart
```

Что замерено на живых endpoint'ах VK (без ключей; воспроизводится через `exchange --dry-run` и
`exchange` с фиктивным секретом):

| Поток | Endpoint | Требует |
|---|---|---|
| Implicit (`response_type=token`) | `oauth.vk.com/authorize` | только id приложения; ключ отдаётся в адресной строке, дольше всех живёт |
| Authorization Code | `oauth.vk.com/authorize` → `oauth.vk.com/access_token` | `client_id`, `client_secret`, `redirect_uri`, `code` — endpoint жив: без секрета отвечает `invalid_client: client_secret is incorrect` |
| VK ID | `id.vk.com/authorize` → `id.vk.com/oauth2/auth` | дополнительно `device_id` от SDK и PKCE-верификатор; без них `device id is missing`. Ключ короткий (`expires_in`, обычно 3600 с), выдаётся `refresh_token` |

И что замерено про само видео (04.10.2026, личный ключ с правом «Видео» на живом аккаунте):

| Проверка | Результат |
|---|---|
| `video.save` + загрузка файла личным ключом | работает: возвращает `video<owner>_<id>` и `access_key` |
| `video.get` на своё обработанное видео | `files: None` |
| `video.get` на видео сообщества | `files: None` |
| `video.get` через 5 с и 35 с после загрузки | `files: None` |
| `direct_url` из ответа | HTML-страница плеера `vkvideo.ru` (скачано 103 525 байт, признака mp4 нет) |

Подробнее, включая разбор того, что в официальной справке прочитать не удалось и почему, —
[docs/vk-id-auth-flow.md](docs/vk-id-auth-flow.md).

## Проверка

```bash
cd <hermes-install>                       # каталог Hermes, где лежит venv/

# канонический прогон (pytest не входит в runtime-venv Hermes)
venv/bin/pip install pytest               # аддитивно; pip check остаётся чистым
venv/bin/python -m pytest <plugin-dir> -q # 156 passed

# поведенческие файлы умеют и самозапуск, без pytest
PYTHONPATH=$PWD venv/bin/python <plugin-dir>/tests/test_vk_adapter.py
PYTHONPATH=$PWD venv/bin/python <plugin-dir>/tests/test_vk_live_loop.py
PYTHONPATH=$PWD venv/bin/python <plugin-dir>/tests/test_plugin_layout.py
PYTHONPATH=$PWD venv/bin/python <plugin-dir>/tests/test_vk_profiles.py
```

Файл `tests/test_vk_user_token_tool.py` использует фикстуры pytest (`tmp_path`, `monkeypatch`,
`capsys`) и запускается только через pytest.

Пути разрешаются автоматически (`tests/_paths.py` находит runtime через `$HERMES_INSTALL`, стандартную
раскладку `~/.hermes/hermes-agent` или текущий каталог) и регистрирует каталог плагина как пакет `vk`,
поэтому запускать можно откуда угодно — в том числе из клона с дефисом в имени (`hermes-vk`), где имя
каталога не является допустимым именем модуля.

`test_vk_live_loop.py` поднимает на `127.0.0.1` мок VK API и Long Poll и проводит через настоящий
адаптер полный цикл `connect() → long poll → входящее → send() → disconnect()`, включая восстановление
после `failed=1` (сдвиг курсора) и `failed=2` (переподключение сессии) и повтор с тем же курсором при
транспортной ошибке. Настоящий токен и сеть ему не нужны.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `groups.getLongPollServer` → ошибка 15/27 | у ключа нет права «Управление сообществом» либо Long Poll API выключен |
| Бот не видит сообщения | в Long Poll не отмечено «Входящие сообщения»; проверьте также, что шлюз перезапущен после правки `.env` |
| Сообщения приходят, ответов нет | отправитель не в `VK_ALLOWED_USERS` (либо ждёт подтверждения pairing-кодом) |
| Нажатие кнопки «крутится», в логе ошибка 912 | в сообществе не включён «Чат-бот» |
| Кнопка «крутится» бесконечно, в логе пусто | обрыв long poll: VK буферизует события ~5 минут и повторяет их для того же `ts`, но новый `getLongPollServer` отдаёт **текущую** позицию — переподключение сессии «перепрыгивает» накопленное. Адаптер при транспортной ошибке повторяет с тем же `ts`; в логе есть строки `message_event received` и предупреждение при неизвестном типе апдейта |
| `901 Can't send messages for users without permission` | сообщество не может писать первым: пользователь должен один раз написать ему сам. На «пустом» сообществе стартовое уведомление шлюза падает с 901 — это норма, не ошибка конфигурации |
| Разметка исчезла целиком | VK молча обнуляет весь `format_data`, если в нём есть неподдерживаемый тип. Адаптер отправляет только `bold`/`italic`/`url`; `~~strike~~` снимается до отправки |
| Ответ приходит с блоком «💭 Рассуждения» | выключите per-platform вывод: `display.platforms.vk.show_reasoning: false` |
| Плагин отключился после `hermes update`, в логе `uv lock exited 2` / `TOML parse error` | в каталоге плагина оказался `pyproject.toml`: менеджер плагинов принял его за сборку пакета. Файл удалить (конфиг тестов живёт в `pytest.ini`), затем `hermes plugins enable vk-platform`. От этого защищает `tests/test_plugin_layout.py` |
| `Platform 'VK' requirements not met` | пустой `VK_TOKEN` в `.env` профиля |
| `hermes send ... MEDIA:...` без текста | ядро разрешает медиа без подписи только для telegram/discord/matrix/… — добавьте короткую подпись рядом с `MEDIA:` |
| `.mp4` приходит документом, хотя личный ключ прописан | проверьте `scripts/vk-user-token.py status`, затем `hermes gateway restart`: ключ читается процессом при старте. Признак в логе — `VK: video upload refused (5) — sending … as a document` (именно так выглядел дефект 04.10.2026: путь cron/`hermes send` создавал клиент без личного ключа) |
| Входящее видео приходит пометкой `[видео: …]` | это не поломка и ключом не лечится: VK не отдаёт ссылок на файлы (замерено 04.10.2026) |
| `vk-user-token.py exchange` → `invalid_client` | не найден или неверен секрет приложения: проверьте `~/.hermes/vk-app-secret` (права 600) или `VK_APP_SECRET` |
| `vk-user-token.py exchange --flow vkid` → `device id is missing` | VK ID рассчитан на SDK на веб-странице: нужен `device_id` и PKCE-верификатор, которых «ручной» поток не даёт. Проще легаси-потоки (`implicit` или `code`) |

## Разработка

- Тесты запускаются через `pytest` (см. «Проверка») либо самозапуском — оба пути поддерживаются.
- `pytest.ini` намеренно, а **не** `pyproject.toml`: менеджер плагинов Hermes считает любой
  `pyproject.toml` в каталоге плагина сборкой пакета, копирует плагин в `plugin-sources/<key>/` и
  запускает `uv lock`; без `[project].name`/`version` это падает, и плагин отключается на следующем
  `hermes update`. Тест `tests/test_plugin_layout.py` следит, чтобы такой файл не появился.
- `filterwarnings = error` в `pytest.ini` (именно `error`, **не** `error::RuntimeWarning`): тест,
  вызывающий async-метод без `await`, создаёт корутину, которую никто не исполняет, и «проходит»
  вхолостую. Предупреждение приходит из деструктора, поэтому категорийный фильтр его не ловит —
  безусловный `error` ловит. Побочная польза: строгий режим сразу вскрывает незакрытые event loop.
- Проверяя тест, ломайте ровно ту ветку, которую он покрывает, в копии каталога: тест обязан упасть.
  Иначе легко проверить не то, что кажется. И проверьте, что копия **зелёная до мутаций**: однажды
  копия не нашла runtime (`HERMES_INSTALL`) и падала на сборе тестов, из-за чего «пойманными» выглядели
  все мутации подряд.
- Отправка файлов живёт в **двух** местах: живой ответ агента идёт через адаптер, а доставка по
  расписанию и `hermes send` — через отдельную функцию, которая создаёт собственный клиент. Правя
  доступ к ключам, проверяйте оба: 04.10.2026 личный ключ был прописан и работал при прямом вызове, но
  второй путь его не передавал — и видео молча уходило документом.
- Секреты не передаются аргументами командной строки и не печатаются: инструмент читает их из файла с
  правами 600 и пишет результат прямо в `.env`.

## Ограничения

- Вложения кроме фото/документов/голосовых (опросы, истории, стикеры и т. п.) не обрабатываются.
- Видеозвонки и прямые трансляции VK вне области задачи.
- Исходящие голосовые требуют `ffmpeg`; без него отправляется документ.
- **Входящее видео скачать нельзя** — ни с личным ключом, ни без него: VK не отдаёт ссылок на файлы
  (`video.get` возвращает `files: None`; `direct_url` — HTML-страница плеера `vkvideo.ru`, скачанные
  103 525 байт без признака mp4). Замерено 04.10.2026 на своём и на чужом видео, повторно через 5 и
  35 секунд после загрузки. Поэтому входящее видео остаётся пометкой
  `[видео: <название>, <длительность> с]`.
- **Личный токен нужен только для нативной отправки видео** (`video.save` — пользовательский метод;
  ключу сообщества VK отвечает ошибкой 5 «User authorization failed», проверено живьём 03.10.2026).
  Без него `.mp4` уходит документом — файл доезжает, отчёт не теряется. Вложение приватного видео
  обязано нести `access_key`, иначе получатель видит непроигрываемое видео; адаптер это делает.
  Личный токен — это доступ к вашей странице, поэтому он необязателен, и в логах он маскируется.
- Личный токен, выданный VK ID, короткоживущий (`expires_in`, обычно 3600 с) и требует `refresh`;
  канал читает ключ из `.env` при запуске, поэтому после обновления нужен `hermes gateway restart`
  (либо регулярный `refresh` по расписанию).
- Резервный опрос (если включён) видит сообщения, пришедшие **после** подключения канала: то, что
  прилетело, пока шлюз был выключен, остаётся в VK. Дубликатов он не создаёт — всё проходит через общий
  дедупликатор.
