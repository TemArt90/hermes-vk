## 1.7.0 — 2026-10-03

- **Резервный опрос истории** (`VK_FALLBACK_POLL_ENABLED`, по умолчанию выключено) — страховка под

  `VK_FALLBACK_POLL_INTERVAL_SECONDS` (по умолчанию 60 с, минимум 15) опрашивает последние беседы

  опроса не роняет канал, а дубликаты невозможны — всё проходит через общий дедупликатор. Ограничение
  записано в README: видны сообщения новее момента подключения канала.
- Тестов 95 → 100 (+5): маркер «только новое», пропуск при живом Long Poll, выключенность по умолчанию
  и зажим значений, живучесть при сбое клиента, интеграционный сценарий «Long Poll завис — сообщение
  доехало через опрос» на мок-сервере.

## 1.3.0 — 2026-10-03

- Добавлено: **правка сообщений на месте** (`messages.edit`). Длинные ответы и прогресс больше не
  приходят вторым сообщением — ядро обновляет уже отправленное. Учтены два ограничения VK: у
  `messages.edit` нет `format_data`, поэтому правка идёт простым текстом (`to_plain`; разметка живёт
  только в исходной отправке), и правка не умеет разбивать — содержимое, не влезающее в одно
  сообщение, возвращается вызывающему с `success=False`, и он отправляет заново с обычной разбивкой.
- Добавлено: **реакции-подтверждения** (`VK_REACTIONS_ENABLED=true`, по умолчанию выключено): 👌 на
  входящее сообщение, пока агент работает, затем 👍 при успехе или 👎 при ошибке; отменённый запрос
  остаётся без реакции. Используются штатные хуки ядра `on_processing_start` /
  `on_processing_complete(event, outcome)`, которые gateway вызывает сам. Номера реакций
  настраиваются (`VK_REACTION_PROGRESS` / `VK_REACTION_OK` / `VK_REACTION_FAIL`, `0` отключает шаг) —
  VK нумерует реакции по сообществу.
- Учтено: реакции адресуются по **`cmid`** (`conversation_message_id`), а не по `message_id` — иначе
  VK отвечает ошибкой 100. Адаптер запоминает пару «чат + сообщение → cmid» на время обработки.
  Ошибки 1009/1010/1011 (нет такой реакции / отключена / предел) логируются и не мешают ответу;
  отсутствие `messages.deleteReaction` в старом API запоминается, и метод больше не дёргается.
- Тесты: 62 (было 50). Правка, адресация реакций и выключенность по умолчанию проверены мутацией:
  сломанная ветка роняет от одного до пяти тестов.

## 1.0.0 — 2026-10-03

Первая публичная версия. Канал ВКонтакте для Hermes Agent: Bots Long Poll на вход,
`messages.send` на выход, без вебхука и домена.

**Что входит**

- Транспорт: `groups.getById` → `groups.getLongPollServer` → `a_check` (wait=25, version=3),
  восстановление после `failed=1/2/3`, повтор с тем же курсором при транспортной ошибке
  (иначе VK молча пропускает события, накопившиеся за время обрыва).
- Разметка: Markdown → `format_data` (`bold`/`italic`/ссылки) с офсетами в UTF-16,
  allowlist типов (одна неподдерживаемая конструкция обнуляет весь `format_data`),
  нарезка под лимит VK, таблицы → «заголовок + пункты», цитаты → курсив.
- Медиа: приём фото/документов/голосовых в кэш агента; отправка через
  `photos`/`docs.getMessagesUploadServer`; подпись и вложение одним сообщением;
  голосовые — Ogg Opus через ffmpeg с деградацией в документ.
- Кнопки: inline-клавиатура + `message_event`, общая конвенция Hermes
  (clarify / подтверждение опасных команд / слэш-подтверждения), обязательный ответ
  на нажатие, отказ неавторизованным, одноразовость кнопок.
- Доступ: штатные гейты Hermes + pairing-код, без собственной логики allowlist.
- Доставка по расписанию: `deliver=vk` (в том числе в списке `email,vk`).

**Проверено**

- 32 автотеста (`pytest`), включая живой цикл на мок-сервере VK: `connect → long poll →
  входящее → send → disconnect`, обрыв соединения и восстановление сессии.
- Живым сообществом: маршрут «входящее сообщение → сессия агента → ответ»,
  разметка на проводе (`format_data` через `messages.getHistory`), загрузка картинки
  с подписью одним сообщением, доставка крон-отчёта.

**Чего в этой версии нет**

- Голосовые исходящие проверены только при наличии `ffmpeg`; без него файл уходит документом.
- Работа с «историями», опросами и другими типами вложений VK не поддержана.
