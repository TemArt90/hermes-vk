# Диагностика VK-канала

Здесь собраны случаи, которые реально случались на этом канале, с точным кодом ошибки и лечением.
Каждый пункт таблицы — не теория: это либо ошибка из `errors.log`, либо наблюдение из живого канала.

## 1. Где смотреть

```bash
# состояние канала и версия плагина
hermes plugins list | grep -i vk

# что говорит адаптер (сообщения с префиксом «VK:»)
grep -i "VK:" ~/.hermes/logs/agent.log | tail -50

# ошибки
grep -i "vk" ~/.hermes/logs/errors.log | tail -20
```

Адаптер поднимается в шлюзе (`hermes gateway`), не в отдельном процессе. Успешный запуск пишет в лог
строку вида:

```
VK: connected to community <название> (id=<id сообщества>)
```

Если этой строки нет — смотреть следующий раздел.

## 2. Канал не поднимается

| Симптом в логе | Причина | Лечение |
|---|---|---|
| `Plugin 'VK' requirements not met` | в профиле пустой `VK_TOKEN` | вписать токен в `~/.hermes/.env`, перезапустить шлюз |
| `VK: token is missing` | токен есть, но не подхватился: переменная в другом профиле | проверить, что правится `.env` активного профиля (`hermes profile show`) |
| `VK: resolve_group failed (27): group authorization failed` | токен не от того сообщества | перевыпустить ключ в настройках нужного сообщества |
| `VK: resolve_group failed (15): access denied` | у ключа нет права «Управление сообществом» или выключен Long Poll API | выдать право ключу и включить Long Poll API в настройках сообщества |
| `VK: failed to acquire long poll server` после ретраев | сообщество без включённого Long Poll API либо канал отключён | включить Long Poll API (версия ≥ 5.199) |

Сообщество определяется по токену через `groups.getById` — отдельный `VK_GROUP_ID` не нужен, поэтому
неверный `group id` как причину можно исключить сразу.

## 3. Сообщения не ходят

| Симптом | Причина | Лечение |
|---|---|---|
| `901 Can't send messages for users without permission` | пользователь ни разу не открывал диалог с сообществом | пусть напишет боту первым — после этого разрешение у сообщества появляется |
| `912` при отправке сообщения с кнопками | у сообщества не включён «Чат-бот» | Управление → Сообщения → Настройки для бота → включить |
| `6 Too many requests per second` | больше одного исходящего в секунду | штатное: адаптер сам повторяет с задержкой; если повторяется — проверить, не дублируются ли кроны |
| Бот молчит в беседе, хотя в дискуссии отвечает | включён гейт упоминаний: в беседах бот отвечает только по обращению | `VK_REQUIRE_MENTION=true`; отключить или настроить `VK_REQUIRE_MENTION_BY_PEER` |
| Текст пришёл «сырым» — с `**` и `|---|` | сообщение ушло мимо рендера (например, сторонним скриптом напрямую в VK API) | штатный путь — `hermes send --to vk:<peer>`; он рендерит разметку |
| Сообщение обрезано | VK режет на 4096 символах, адаптер — на 4000 | норма: длинные ответы приходят несколькими сообщениями |

## 4. Медиа

| Симптом | Причина | Лечение |
|---|---|---|
| `docs.getMessagesUploadServer failed (100): peer_id is invalid` | дефект версий ≤ 1.3.0: документы и голосовые уходили с `peer_id=0` | обновить плагин до ≥ 1.3.1 |
| Голосовое пришло файлом, а не «пузырём» | входной файл не Ogg Opus, либо рядом нет ffmpeg | проверить `ffmpeg -version`; адаптер ищет его в `PATH`, затем в `<HERMES_HOME>/tools/ffmpeg-*/bin/` |
| `upload failed (405)` | upload-серверы VK периодически отвечают так на подряд идущие загрузки | штатное: `upload_with_retry` повторяет; если постоянно — загрузки идут слишком часто |
| Файл больше лимита не отправляется | `VK_MAX_ATTACHMENT_BYTES` (по умолчанию 20 МБ) | поднять лимит осознанно: VK ограничивает размеры по типам |
| Входящее видео пришло пометкой `[видео: ...]` | ключ сообщества не может вызвать `video.get` | ограничение VK; для скачивания нужен пользовательский токен (в этом плагине не используется) |
| Входящий файл не скачался | `VK_DOWNLOAD_ATTACHMENTS=false` или размер выше лимита | включить переменную / поднять лимит |

## 5. Кнопки, реакции, правка сообщений

| Симптом | Причина | Лечение |
|---|---|---|
| Нажал кнопку — «крутится», нового сообщения нет | VK показывает ответ нажатия (snackbar) на **старом** сообщении, а не присылает новое | это норма; ответ ищите в исходном сообщении с кнопками |
| Кнопки не появились | `VK_COMMAND_KEYBOARD` выключен, либо сообщество без «Чат-бота» (912) | включить переменную и/или настройку сообщества |
| `messages.sendMessageEventAnswer 100: invalid event_id` | `event_id` одноразовый, ответ отправляли дважды | штатное: адаптер отвечает один раз; повтор означает дублирование обработчика |
| Реакции не появляются | `VK_REACTIONS_ENABLED=false` (по умолчанию выключено) | включить переменную; прогресс/итог настраиваются `VK_REACTION_PROGRESS/OK/FAIL` |
| `1009` при реакции | этой реакции нет в списке сообщества | выбрать другую из допустимых VK |
| `1010` / `1011` при реакции | реакции отключены в сообществе / исчерпан лимит | включить реакции в настройках сообщества |
| Правка вернула текст без разметки | `messages.edit` в VK не поддерживает `format_data` | норма: разметка живёт только в исходной отправке |
| В чате видны «рассуждения» агента | включён вывод reasoning для VK | в `config.yaml`: `display.platforms.vk.show_reasoning: false` |

## 6. Long Poll

| Симптом в логе | Что это | Что делать |
|---|---|---|
| `VK: long poll error #N (...); retrying from the same cursor in Xs` | транспортный сбой; курсор сохраняется намеренно (VK кэширует апдейты ~5 минут) | ничего: адаптер переподключается сам |
| `VK: long poll session dropped (failed=2)` | VK инвалидировал сессию | ничего: адаптер перезапрашивает `groups.getLongPollServer` |
| Канал «затих» на несколько минут и ожил | сессия Long Poll переустанавливалась | если повторяется часто — присмотритесь к сети хоста (DPI может резать долгие соединения) |
| Сообщения обрабатываются дважды | сломан дедупликатор (`MessageDeduplicator`, окно 900 с) | проверить, не запущено ли два шлюза: `pgrep -af "hermes gateway"` |

## 7. Что приложить к вопросу о проблеме

1. Версию: `hermes plugins list | grep -i vk` и `git -C ~/.hermes/plugins/platforms/vk describe --tags`.
2. Последние 50 строк с префиксом `VK:` из `agent.log`.
3. Код ошибки VK из ответа (число в скобках) — по нему причина находится однозначно.
4. Что именно отправлялось: сообщение, файл, кнопка, реакция.

Подробности по API (какие методы умеет ключ сообщества, почему `format_data` обнуляется целиком, как
адресуются реакции) — в `docs/vk-api-notes.md`.
