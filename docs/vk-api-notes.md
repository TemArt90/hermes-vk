# Заметки по VK Bots API — то, что неочевидно из документации

Собрано при разработке и проверке этого плагина на живом сообществе. Здесь только находки, которые
стоили времени: поведение, где VK не возвращает ошибку, а делает что-то другое, и места, где
интуиция подсказывает неверное решение.

## Транспорт и курсор

**При транспортной ошибке повторяйте с тем же `ts`, а не переподключайте сессию.** VK хранит апдейты
около 5 минут и повторяет их для того же курсора, но `groups.getLongPollServer` отдаёт **текущую**
позицию. Значит, переподключение после оборванного сокета молча перепрыгивает всё, что пришло за время
обрыва. Симптом дорогой в диагностике: кнопка «крутится вечно», а в логе шлюза **пусто** — ни
`message_event`, ни ошибки, хотя событие в сообществе включено и `groups.getLongPollSettings`
подтверждает его. Правило: при исключении — пауза и повтор с тем же `ts`; новую сессию берём только при
`failed=1/2/3` (или после нескольких подряд неудачных попыток). Регрессионный тест: мок отдаёт HTTP 500
на один `a_check`, следующий опрос обязан использовать тот же `ts` — если вернуть прежнюю логику, тест
падает.

**Логируйте неизвестные типы апдейтов.** `else: pass` в диспетчере делает «событие не пришло» и «мы его
выбросили» неразличимыми. Одна строка INFO на неожиданный тип превращает третьи поиски вслепую в ответ
за пять секунд.

**Второй потребитель Long Poll не ломает, но двигает курсор.** Для живой диагностики предпочитайте
read-only методы (`messages.getHistory`, `messages.getConversations`) — они не трогают позицию.

## Ошибки, которые выглядят как баг, но им не являются

| Код | Текст | Что на самом деле |
|---|---|---|
| 901 | `Can't send messages for users without permission` | Сообщество **не может писать первым**: пользователь должен один раз написать ему сам. Признак — `messages.getConversations` возвращает 0 диалогов. Обойти серверной стороной нельзя; стартовое уведомление шлюза на «пустом» сообществе падает с 901 и это норма |
| 912 | `This is a chat bot feature, change this status in settings` | В сообществе не включён «Чат-бот» (Управление → Сообщения → Настройки для бота). До включения клавиатуры невозможны: `send_clarify` должен деградировать до нумерованного текста, а не терять вопрос |
| 15 / 27 | нет права / ключ отозван | У ключа нет «Управления сообществом» либо Long Poll API выключен |
| 100 | `invalid event_id` | `messages.sendMessageEventAnswer` проверяет аргумент: одноразовый `event_id` после первого ответа становится невалидным. Для живого нажатия это не воспроизводится |

## Разметка

**VK молча обнуляет весь `format_data`, если в нём есть неподдерживаемый тип.** Не ошибка, а `null` в
поле и доставленный текст без форматирования. Доказательство: `bold` + `italic` сохраняются; добавление
одного элемента `strike` → VK хранит `null`. Вывод: держите allowlist типов (`bold`/`italic`/`url`) —
одна неверная конструкция не должна снимать разметку со всего ответа.

**Офсеты считаются в UTF-16 code units** (`len(text.encode("utf-16-le")) // 2`). Наивное «сначала
рендер, потом обрезка по лимиту» разрезает спаны: сначала нарезка, потом расчёт офсетов на каждый
кусок.

**Таблиц у VK нет.** GFM-таблица приходит литеральными `|` и на телефоне превращается в кашу, поэтому
её нужно конвертировать в «заголовок + пункты» **до** рендера разметки. Тонкость: модели часто отдают
таблицу «ключ|значение» с пустой строкой заголовка (`|||` / `|---|---|`) — если сопоставлять заголовки
позиционно, получаются пункты вида `• : значение`. Имена заголовков нужно совмещать с **ячейками
значений** (пропуская пункт заголовка, когда первая колонка — метка строки). Одиночная колонка
(`| a |` над `|---|`) таблицей намеренно не считается: разделитель требует двух групп дефисов, иначе
под правило попадёт обычная горизонтальная линия `---`. Код в ``` остаётся кодом — таблицу внутри
ограждения не трогаем.

**Проверяйте на проводе, а не по логам.** `messages.getHistory` возвращает `format_data` и фактически
доставленный текст, то есть подтверждает или опровергает разметку end-to-end. Именно так найдена
проблема со `strike`.

## Кнопки и колбэки

- Клавиатура — JSON `{"inline": true, "buttons": [[{"action": {"type": "callback", "label": …, "payload": "<json>"}}]]}`;
  label ≤ 40 символов, payload ≤ 255 байт.
- **Нажатие обязательно подтверждать** `messages.sendMessageEventAnswer`, иначе кнопка у пользователя
  крутится бесконечно.
- Ответ на нажатие — **всплывающая подсказка, а не сообщение**, и на старом сообщении клиент может её
  вообще не показать. «Нажал и ничего не увидел» — не признак поломки: смотрите в логе `message_event
  received` / `button press …` (доставка состоялась) и `could not answer button event` (не удалось
  ответить).
- Индексы кнопок: payload нумерует варианты **с нуля** (`enumerate`), а пользователь, набирающий «2»
  текстом, попадает в 1-based парсер ядра. Выбор всегда берётся из `_entries[id].choices[idx]` и
  отправляется **меткой**, не числом.
- **Никогда не синтезируйте строку-ответ для кнопки**, которой нет в списке вариантов: резолвер кладёт
  текст дословно в ответ пользователя, и агент начнёт действовать по тексту, которого пользователь не
  писал. Индекс вне диапазона — отказ, а не «choice N».

## Медиа

- `standalone_sender_fn` получает `media_files` как **кортежи** `(path, is_voice)`
  (`BasePlatformAdapter.filter_media_delivery_paths`). Если обращаться с ними как со строками, падает
  на `os.path.exists` с `stat: path should be string… not tuple`.
- **Медиа без подписи отклоняет ХОСТ, до плагина**: общий путь отправки не принимает пустой текст с
  `MEDIA:`, если платформа не входит в жёстко заданный список ядра. Решение — короткая подпись рядом с
  `MEDIA:` в том же сообщении.
- **VK несёт текст и одно вложение в одном сообщении**, поэтому подпись из первого куска должна ехать с
  первым файлом, а не стоить второго сообщения.
- Загрузка фото сообщества: `photos.getMessagesUploadServer` с `peer_id=0`; голосовые —
  `docs.getMessagesUploadServer` с `type=audio_message`.

## Прочее

- `~/.hermes/config.yaml` защищён от прямой записи агентом — используйте `hermes config set`.
- Чтобы отключить блок «💭 Рассуждения» только для канала, задайте per-platform override
  `display.platforms.vk.show_reasoning: false`.
- Проверяя тест, ломайте ровно покрываемую ветку в **копии** каталога плагина: тест обязан упасть.
